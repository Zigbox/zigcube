# C4: the mesh plan, readiness and `why grant`

*Decided 2026-11-13, by C4 slice 2 (`src/mesh_plan.zig`, `src/why_grant.zig`).*

- **Readiness without `min_ready_ms`.** A replica is ready when the node it is assigned to has an
  observed record for it, `running`, at the replica's generation, and, if the service has a health
  check, last reported healthy. Replica observed records carry no assignment epoch (only job
  reports do), so the epoch is compared only when a record names one. A `min_ready_ms` dwell is not
  in the brief and is not built.
- **Draining** is an observed replica that is not stopped and has no desired record (the
  replica controller has removed it). A draining replica is never an endpoint, and an accept's
  `open` needs the replica ready and not draining.
- **Endpoint order.** Endpoints on the planning node come first, then the others, each group
  rotated by a Wyhash of the source replica's id, so sources spread over the destination's
  replicas and one source always tries them in the same order.
- **ZC-W0704 is reported by `why grant`** (verdict `no_source`). Apply has no warnings mechanism
  today; the apply-time warning is left to slice 9 with the CLI.
- **Attribution** (`allows[].added`, `removed`) scans the destination's newest
  `decisions_per_subject_max` index entries, keeps those with action `grant` and matches their
  change text (`"{from} → {port} added|removed"`). A decision lost to retention is simply absent.
- **API path** is `GET /v1/why/grant/{from}/{to}/{port}`, with `connection` as an alias
  (docs/api.md). The CLI rendering is slice 9.
- **Not done here:** `why service` listing the service's grants out and in (left for a later
  slice); the agent does not publish mesh endpoints yet (slice 3), so until then every
  destination answers `no_endpoint` outside tests.
