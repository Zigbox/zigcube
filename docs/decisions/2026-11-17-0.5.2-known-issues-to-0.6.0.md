# Cube 0.5.2 ships with five release-review findings open, to be fixed in 0.6.0

*Decided 2026-11-17, by the owner (accepted in writing; recorded by the supervisor's fix session).*

The two independent release reviews of #272 (reviews
[5927120432](https://github.com/Zigbox/zigcube/pull/272#pullrequestreview-5927120432) and
[5927352205](https://github.com/Zigbox/zigcube/pull/272#pullrequestreview-5927352205), both on
c6e3bae) raised the findings below. The owner accepts that Cube 0.5.2 is released with them open.
Each is fixed in the 0.6.0 top-to-bottom review, not in 0.5.2.

1. **The agent uses plain HTTP to a non-loopback `--server`.** Without `--ca`, `zcube-agent`
   talks plain HTTP to whatever address `--server` names, though the server serves plain HTTP on
   loopback only (ZC-E0106). A node configured that way takes assignments and posts `relay.pub`
   unauthenticated. Review 5927120432, `src/agent_config.zig:325-326`.
2. **A cancelled job that the job fence stops ends `failed`, cause `unreachable`, not
   `cancelled`.** When `/runs` fails long enough for the fence (#270) to stop a job whose cancel
   was already committed, the cause the fence recorded wins over the server's `cancel`, on a node
   that stayed `ready`. Review 5927352205, item 4, `src/agent_jobs.zig:203-208` and `:733-746`.
3. **No test fails when the supervisor's fail-closed check is removed.** `relay-teeth` covers the
   fake supervisor only; nothing removes `zigbox_supervisor`'s `kill_unrelayed`, and the teeth
   count any exit 1 as caught. Review 5927352205, item 6, `build.zig:373`.
4. **No test of the job fence's timing.** No test pins the fence to the time the runs read was
   sent: a fence stamped after the read returns passes every test. Review 5927352205, item 5,
   `src/agent_jobs.zig:272`.
5. **The reviews' NITs.** Review 5927352205, items 7 to 10: the fence skips a job container whose
   start record is missing or damaged; the trust policy file's directory is not checked; the
   `sim-c1-runs-unread` replay lines name a runner no step installs; and #270's behaviour is in
   `docs/decisions/` only (docs/agent.md, authority.md:561 and docs/mtls.md are out of date).

Reasons: none of these is a MUST of either review, and the owner chose to ship 0.5.2 rather than
hold it for them. Each gap here is closed in 0.6.0's review, with a test where the finding names
a missing one.

Where: the two reviews on #272; `docs/agent.md`, `docs/authority.md`, `docs/mtls.md` (to be
updated in 0.6.0).
