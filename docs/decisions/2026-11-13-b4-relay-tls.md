# B4 slice 2: the relay over TLS, and failing closed

*Decided 2026-11-13, by the slice (B4 slice 2, second implementer). Points marked "ask" wait on
the supervisor.*

## The relay over TLS

- **The key.** The job's supervisor makes the run's Ed25519 pair and keeps it only in its own
  memory. It writes `relay.pub` into the container's directory: one line,
  `<job> <epoch> <image digest hex> <public key hex>` (`relay_tls.Request`). The agent POSTs it
  (`agent_relay_certs.zig`) and writes the answer as `relay.crt` (DER), or `relay.refused` and a
  `relay.log` line on ZC-E0706. A certificate whose key is not the run's is ignored, so nothing
  in the directory can change whose key signs.
- **No certificate, no dial.** The relay's acceptor waits for `relay.crt`; until then, and for
  ever after `relay.refused`, a job's connection is closed without dialing upstream.
- **Half close.** `tls_conn` has no half close: its `close` sends `close_notify` and stops
  reading. So the job's end of input closes the upstream connection, and what the upstream sends
  after it is dropped. A protocol that half-closes and then waits for the answer does not work
  through a TLS relay; B3's plain relay is unchanged.
- **The Zigbox runtime** (`zigbox_supervisor.zig`) still serves a plain relay. It gets the TLS
  path in slice 4, with `demo-b4`. Until then a job with a TLS relay on `--runtime zigbox` fails
  open (connects in plaintext): report, not fixed here.

## Failing closed

- **No relay, no workload.** A relayed command never starts when its relay could not be opened:
  ZC-E0702, as in B3.
- **Relay gone, workload gone.** If the relay's listener stops while the run lives (the acceptor
  ends before `stop`), the relay kills the command (SIGKILL) and writes ZC-E0702 to `relay.log`:
  "the relay's listener stopped while the job ran (...): the job's command was killed". The
  supervisor then records the run as killed by signal 9. **Ask:** this reuses ZC-E0702 rather
  than registering a "relay stopped" code; the brief says to ask before adding one.
- **Test faults** (fake runtime, `<state-dir>/faults/<name>`): `relay_open` (read at `start`; the
  runtime writes `relay.fault` and the supervisor fails the relay's opening) and `relay_stop`
  (applied on `list`; `SIGUSR1` to the supervisor, which shuts the listener down).
- **Teeth.** `zig build relay-teeth` runs the two "relay fail closed" tests of
  `src/fake_runtime_test.zig` against agents with one half off
  (`src/zcube_agent_relay_teeth_outlive.zig`, `..._unrelayed.zig`, switched through root
  constants) and passes only if each fails. Not in `check`.

## Known conflict: demo-b3

`src/demo_b3.zig`'s server configuration has no `.cluster`, no `server_name` and no `server_ca`,
and CI builds demo-b3 with `-Doptimize=ReleaseSafe`, where `.plain` is refused. So demo-b3 fails
at configuration load on this branch. Not fixed here (it needs a TLS upstream on the VM rig,
slice 4's work, or a ruling that demo-b3 runs Debug): report.
