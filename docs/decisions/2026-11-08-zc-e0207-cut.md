# ZC-E0207 for an oversized job record: cut (2026-11-08)

Carried from the review of #178 (issue #180, then #183): ZC-E0207 blames the environment (503)
for a record that is too large.

**Decision: cut for jobs; nothing to change in `job_api`.** A job whose run record would encode
over `job_run_bytes_max` (16 KiB) is already refused 400 ZC-E0130 naming the largest field
(`check_run_size`, before any store call), and the Job record holds the same fields as the run, so
it is under `store_value_bytes_max` too. No job request reaches ZC-E0207 for size; a run that did
would be ZC-B0005 (our defect, 500).

What remains is the generic `records.encode` path for other records (service specs, `src/apply.zig`
under #184), where an oversized record stays 503 ZC-E0207 with a cause naming both sizes
(`docs/api.md`). Changing that means a status code or a new code, which is the owner's to decide
and outside this change; it is not done here. If it is wanted, the choice is to refuse the
oversized spec in the apply handler with ZC-E0130 before the store, as `check_run_size` does.
