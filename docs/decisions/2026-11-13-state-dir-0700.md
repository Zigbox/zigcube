# A state directory the server or agent creates is 0700

Date: 2026-11-13. Status: supervisor-approved (user-visible: the mode of a directory we create).

## What happened

A reviewer saw `zig build check` fail on fb385b2 in `src/server_ca.zig` ("a CA certificate near
its end is made again"), and the test alone failed too. The cause was not the date or a flake
(0 failures in 520+ runs under umask 022). It was the umask. `std.testing.tmpDir`, and the server's
own `createDirPath`, made directories under the process umask. Under 002 (a login umask with a
private group) the result is 0775, and `peer_files.check_dir` refuses that (ZC-E0806). `check`
runs the tests as `tester` through `runuser`, which keeps root's 022, so it passes here; a shell
with umask 002 fails.

The same fault is in production. A server (or an agent) started under umask 002 on a state
directory that does not exist yet creates it 0775 and then refuses it, failing closed with
ZC-E0806.

## Decision

- `peer_files.make_dir` creates the state directory, and any missing parents, with mode 0700.
  `server_ca.open` and `agent_peer.open` use it. `server_remember` makes the same directory
  first, when a server starts, so it creates it 0700 too. A directory that already exists keeps its mode,
  and `check_dir` still refuses one that group or others can write.
- ZC-E0806's fix line for a directory says to remove group and other write (chmod 0700). It used
  to say "mode (0600)", which is wrong for a directory.
- Tests no longer depend on the umask. `TestDir` and the server, CLI and agent test rigs set
  their temporary state directories to 0700, and the revoked files the tests write are 0600.
  `server_ca` has two regression tests that force umask 002: the CA tests still hold, and a
  fresh two-level state directory is created 0700 and accepted. With the old `createDirPath`,
  the second test fails.

## Not changed

- Other directories created with `createDirPath` (images, container and local-mode
  directories) are not checked by `check_dir`, so they keep the umask's mode.
