# CI: build cache, toolchain cache, split jobs, affected jobs only on pull requests
*Ported from Zigbox's `docs/decisions/2026-11-04-ci-affected-demos.md` (Zigbox PR #44). Requested by the owner, 2026-11-04.*

A run on main took 812 s (13.5 min, run 41851215231). The longest job was `core on wasm32` at 13 min (the simulations were steps in it); every job spent 0.8 to 2 minutes downloading Zig.

1. **Zig build cache** (`.github/actions/zig-cache`) for `format, build, test`, `core on wasm32` and the new `simulations` job, keyed per job. Not for the demos, the Postgres store suites, the fault tests or the Zigbox smoke: a real database, real processes or a VM dominates them. Scratch directories the tests and smokes write under `.zig-cache` are excluded (`/**` is needed to exclude a directory's contents) and removed on restore. The size guard runs on every restore and looks at the directories, not `cache-matched-key`; over 1000 MB it starts cold. Steps with side effects (tidy, `errors-site-check`, the Node checks, the store suites, the smokes, the demos) are never skipped by a restored entry; a test binary is skipped only when byte-identical to one that passed.
2. **Zig toolchain cache** in `setup-zig`: one entry for the unpacked toolchain, the checksum verified on a miss.
3. **`concurrency` with `cancel-in-progress` for pull requests** was already there; `labeled` is added to the pull-request types so `full-ci` starts a run.
4. **`core on wasm32` split** into it (wasm-check twice, wasm-test, console-wasm) and `simulations (sim-c0, sim-c1)`; the steps are unchanged.
5. **Affected jobs only on pull requests** (`.github/ci-changes.sh`, table-tested by `.github/ci-changes-test.sh` in the `changes` job before it classifies). `code` (format, build, test, wasm, simulations) runs for every change that is not documentation. The Postgres store suites, `demo-c0`, `demo-c1` and the Zigbox smoke run when a path can affect them: a demo's own driver files run that demo only; the Zigbox adapter and its smoke run the smoke only; the store suites' own files run the store jobs only; tests of the code, the simulations, `web/`, `tools/` and similar run none. `build.zig`, `build.zig.zon`, `.github/`, `fixtures/`, `demo/`, the shared demo driver and **any path no rule names** run everything. A push to `main`, a `claude/release-*` pull request and a `full-ci` pull request run everything; a documentation-only push to `main` still skips the jobs, as before.

The owner accepts, as for Zigbox, that a break the filter did not select can first show on `main`. When one does, widen the rule in `ci-changes.sh` and add the path to the table test.

Changed from the old behaviour: the Zigbox smoke used to run on a pull request only for `src/zigbox_*`, `src/agent*`, `fake_*`, `runtime*`, `host_*`, `diag*` and the build files; now it runs for those and for any unnamed path (the server, the store backends, the core), because an unknown path runs everything. Every job keeps its name; `simulations (sim-c0, sim-c1)` is new.
