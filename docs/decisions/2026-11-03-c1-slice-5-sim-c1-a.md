# C1 slice 5, sim-c1: a profile of sim_cluster (Options.c1, --c1), not a new simulator entry

*Decided 2026-11-03.*

C1 slice 5, `sim-c1`: a profile of `sim_cluster` (`Options.c1`, `--c1`), not a new simulator entry. The faults (skew, wedged agents, competing placements) are the cluster simulation's own world with more weight, the invariants need its real controllers, agents and store, and a second copy would drift; the profile adds a `TapStore` beneath the lost-ack layer that checks every committed revision (I1a, I3, I4, I6, I7), the overlap bound (I1b), and at the end of the run `why_acceptance` (I5, §5). I1b is judged on *replacement*: a replica the server replaced (`mark_replica_lost`) must stop on its old node within `lost_grace` + kill latency (5 s) unless that node was wedged (excused, reported); the same-name `duplicates` counter stays 0 under a new replica id, so "duplicates fail" is this check. Four negative tests are separate root files (`sim_c1_teeth_<name>_main.zig`) built with a `c1_teeth` declaration the shipped programs assert away at compile time. Real bug found: apply and the replica controller's decisions embedded no `cause_evidence`, so `why` could not explain them once the cited key changed and was compacted; they now embed it (`src/evidence.zig`).

Where: `src/sim_c1.zig`, `src/why_acceptance.zig`, `src/c1_teeth.zig`, `docs/core.md`
