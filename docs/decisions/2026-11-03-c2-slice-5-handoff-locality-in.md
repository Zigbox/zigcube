# C2 slice 5 handoff (locality in keys and the scheduler)

*Decided 2026-11-03.*

C2 slice 5 handoff (locality in keys and the scheduler). Built as briefed: `/node-store/<node>` v1 (lease-bound, agent-written, advisory, in no compare set) through `Images.summary()` (the fake: `--images` plus the trees the agent started); `precedes` is fit, spread, locality, least allocated, name; Decision v3 carries `locality_bytes` and `node_store_revision`; `why` and the console show them (mock updated). sim-c1 gives every node a seed-chosen image subset and checks L1 (`scheduler.placement_problem`: a placement is no worse on spread, among the nodes that fit at the head, than a fit-and-spread-only order; fit itself stays I6's and I7's, because L1 judging it pre-empted the readiness and allocation negative tests); `sim-c1-teeth-locality` (locality ahead of spread) fails seed 1. **Limits and traps:** (1) the scheduler takes a tree's target sketch from the first node whose summary lists that digest, so a tree no node holds scores 0 everywhere, and the fake cannot model chunks shared between different digests; (2) a malformed or newer `NodeStore` record fails `list_all` in `read_world` and so can stall scheduling (a decode failure of one advisory record should degrade, not stop a pass: decide in slice 6); (3) the filter is empty in the fake summary, slice 6 fills it; (4) the scheduler does not watch `/node-store/`, a changed summary wakes nobody; (5) L1 judges over the head a commit lands on, so it could flag a placement raced by a node turning ready between the scheduler's read and its commit: none seen in seeds 1..400, but treat a one-off L1 as that first. L1 runs in sim-c1 only (not plain sim-cluster).
