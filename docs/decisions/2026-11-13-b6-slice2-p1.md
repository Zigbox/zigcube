# B6 slice 2: tenant labels in sim-c1, check P1 and its tooth

Status: implemented on `claude/b6-slice2`, stacked on `claude/b6-slice1` (PR #235, unmerged).

## What the simulation does now

- The `strong` world gives each node a seeded tenant label set: `{tenant=a}`, `{tenant=b}`,
  `{tenant=a, exclusive=tenant}` or `{tenant=b, exclusive=tenant}`. Jobs carry
  `require = {tenant=<t>}`; every eleventh job names tenant `c`, which no node has.
- Labels come from a `label_prng` seeded `seed ^ 0xb6b6_7e1a_9d03`, so no other draw moves and
  runs without `--strong` are unchanged.
- A host crash fences, and the agent registers again with a label set that is redrawn half the
  time (`relabels=` in the report). A process crash with a valid lease file keeps its
  registration, as before.
- Nodes of even index are never exclusive, and `replicas_for` counts only them in the strong
  world: service replicas have no `require`, so an exclusive node can never take one, and the
  first sweep failed with "a replica is not placed" until capacity was counted that way.

## P1

- Judged in `before_commit`, for each fresh `/assigned/` key, against the `/nodes/<n>` labels
  and the JobRun's `placement.require` read in the same transaction. The judge is its own
  reimplementation of the filter (`tenancy_refused`), not a call into the scheduler.
- Four sentences, all starting `P1:`: a missing label, a differing value, an exclusive node
  without the key, an exclusive node of another tenant. A service replica on an exclusive node
  fails the third.
- Placement-time only. A relabel does not stop running work, so a later relabel is not a
  violation; what must hold is that no new assignment is made against the labels in the store.
- Tooth `placement_exclusive` (`src/c1_teeth.zig`, `sim-c1-teeth-placement_exclusive`) skips the
  exclusive test in `scheduler.placement_refusal`; caught at seed 1 with the "exclusive to a
  tenant the job is not of" sentence. It implies `--strong`.

## Agent change

`agent.Config.labels` (borrowed `[]const []const u8`, default empty) is sent at registration.
No flag or config key was added: that is slice 3's decision (carried item below).

## Evidence

- `--seeds 1..500 auto --c1`: 0 of 500 failed. `--seeds 1..500 150 --c1 --strong`: 0 of 500.
- Of 40 strong seeds at 150 operations, 28 had relabels and 3,950 placements were judged.

## Traps

- The tidy 70-line limit caught `Cluster.init`; the tenant setup is `init_tenants`.
- Capacity: see above. Any new world feature that removes nodes from the service pool must be
  reflected in `replicas_for`.
