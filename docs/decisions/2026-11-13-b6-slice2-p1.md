## The supervisor's ruling on the transient hold (2026-11-14)

The supervisor approved option (A): the server does not refuse a registration whose labels refuse
what the node holds; the controllers move the work off.

- **"At every revision" is met as P1a plus P1b.** The writer rules (writers.zig) let only the
  agent write `/nodes/<n>` and only the scheduler write `/assigned/`, so the registration that
  changes a node's labels and the release of what they refuse cannot share a transaction: at
  least one revision of transient hold is unavoidable. P1a judges every revision (no new
  assignment lands on a refusing node); P1b bounds the transient hold and forbids it at rest.
- **Ending.** A refused run gets the stop the node-lost path writes (`unreachable`, as in
  `job_controller.zig`'s `node_lost` branch) and ends `failed unreachable`; a refused replica is
  replaced under a new id. No new code, ending or bound.
- **The bound.** The ruling: the lease ttl, unless the measured worst case is much tighter, then a
  stated multiple of it. Measured worst case (below, under Evidence): every refused hold was acted
  on before the next one-second scan, so the worst case is under the scan's 1,000 ms resolution;
  the bound is 5 times that, 5,000 ms, below the shortest lease ttl the server admits (8,000 ms).
- **Not checked:** that a refused hold is never reported running under the new tenure. The judge
  does not tie status reports to tenures; noted, not built.
- **The brief.** `docs/briefs/b6.md` is merged on main, so it is not edited; this file carries
  the note that P1's "at every revision" is met as P1a plus P1b.

## Relabel eviction (product)

- A node's registration is one put of `/nodes/<n>` by its agent, and only the scheduler may write
  `/assigned/` (writers.zig). So a relabel cannot move work in the same transaction: the agent
  registers, then the replica or job controller acts, then the scheduler releases. A refused hold
  therefore exists until the controllers' next pass (they wake on the registration); the
  supervisor was told (send_message, with this evidence) before the check was settled, and P1b
  bounds it (below).
- The agent sends labels only with a new tenure (after a fence or a lost disk, `agent.zig`), and
  a new tenure starts empty: an agent restarting within its lease keeps its registration and its
  labels. So in the product a relabel never leaves running work under refusing labels, only the
  old tenure's assignments, which the lost-node and new-tenure paths also clear. The eviction
  below makes that prompt and explicit, whatever path set the labels.
- Replica controller (`refused_placement`): a live or held replica whose node's stored labels
  refuse it (`scheduler.refuses`: the same filter placement uses, with no `require`) is dead: it
  writes a `stop_replica` decision ("...registered again with labels that do not take a service
  replica (...); it is being removed and replaced under a new id", cause `observed` on the
  `/nodes/<n>` key at its revision), compares the replica, its assignment and the node key, and
  deletes the replica. The scheduler places a successor under a new id.
- Job controller (`refused`): a run with no stop whose node's labels refuse its `require` gets the
  existing `unreachable` stop ("the node of the run was registered again with labels that refuse
  the job"); it then ends `failed unreachable` as any unreachable run does. No new enum, code,
  bound or default.
- Tooth `relabel_kept` (`c1_teeth.zig`) turns both off.

## The tenant world now

- As before: `--tenants` (and `auto` operations and the two P1 teeth) gives each node a seeded set
  from `{tenant=a}`, `{tenant=b}`, `{tenant=a, exclusive=tenant}`, `{tenant=b, exclusive=tenant}`
  (even-index nodes never exclusive; `replicas_for` counts only those), jobs `require =
  {tenant=<t>}` per `job_tenant` (every fourth none, every eleventh `c`). All tenant draws come from
  `label_prng`; a run without `--tenants` draws exactly as before.
- New: before one operation in eight until the heal (`label_prng` draws it), an operator
  reinstalls one node with a *different* set (`relabel_node`, `operator restarts` in the report):
  a host crash that loses its disk, state directory and containers, so the agent registers a new
  tenure with the new set. Half the time it picks an odd node and toggles it between its shared
  and exclusive set (`tenant=a` and `tenant=a, exclusive=tenant`), the change that makes service
  replicas refused. A process crash within the lease would not do: the agent keeps its tenure and
  does not send new labels (first measured that way: 5 of 40 tooth seeds caught at a 35 s bound).
  Without operator relabels, refused holds were rare (1 seed of 60 had any) and no tooth could
  bite. `relabels=` now counts only real changes.
- The restart of the tenant world takes the main generator's draw for its restart time, so tenant
  runs differ from the first version's; non-tenant runs do not.

## P1, as judged now (`src/sim_tenancy.zig`)

The judge is independent of the code under test: it records the set each node's agent was
configured with when its registration committed (a new `/nodes/<n>` mod revision; only the agent
writes that key) and checks the stored labels are exactly that set; it takes each job's tenant from
the simulation's own `job_tenant(number)` and checks the stored run's `require` is exactly that; and
it decides with its own three-line rule (`refuses`), not the scheduler's.

- **P1a, at every revision** (`placed_problem`, in the tap's `before`): no new assignment lands on
  a node whose registered labels refuse it.
- **P1b** (`scan`, once a simulated second while the store is healthy, so at least every second
  across every revision that touches `/assigned/` or `/nodes/`): every assignment a registration
  made refused is tracked from when it is first seen, and must be acted on (replica gone; run gone,
  replaced, stopped or ended) within `acted_ms_max` = 5,000 ms counted from the later of its
  first sighting and the store's last failure. The registration wakes both controllers (the job
  controller watches `/nodes/`, the replica controller `/node-status/`), so the fix acts in the
  pass it wakes; the bound is tight so that the slower paths that also clear such holds (the
  node's lost containers, the next resync, at 1 to 30 s) do not hide a missing eviction. A
  sim-check constant, not a product bound. Sentences: "P1: a service replica held on an exclusive
  node past the bound", "P1: a job held on a node that refuses it past the bound".
- **At rest** (`converged`): no assignment its node's registration refuses remains ("P1: a refused
  assignment remains at rest").
- A node with no registration (lease expired, not yet back) is not judged: its holds are I7's and
  the node controller's.

## P1's teeth

- `placement_exclusive` (unchanged): the scheduler skips its exclusive rule; P1a catches it.
- `relabel_kept` (new): no eviction; P1b (bound or at rest) catches it.
- The `require` half: no separate tooth. P1a checks the stored `require` against `job_tenant`
  and rejects a run on another tenant's node; a scheduler that ignored `require` is caught by the
  same `placed_problem` path as `placement_exclusive` (both go through `placement_refusal`). Noted
  here rather than given a 26th runner.

## Evidence

- First version: `--seeds 1..500 auto --c1`: 0 of 500 failed. `--seeds 1..500 150 --c1
  --strong`: 0 of 500.
- The fix (2026-11-14): seeds 1..60, 150 operations, `--c1 --strong --tenants`: 60 of 60 pass;
  the review's replay `7 150 0 --c1 --strong --tenants --heal-at=99` passes.
- Measured worst case for the bound (same 60 seeds): 670 relabels, 32 refused holds in 18 seeds,
  `acted worst=0 ms` in every seed (each hold acted on before the next one-second scan).
- `--seeds 1..40 auto --c1` (tenants on, drawn shapes and profiles): 40 of 40 pass. `zig build sim-c1 -Dtenants`, seeds 1 to 4: native and WASM agree.
- `placement_exclusive`: 15 of 20 seeds caught (100 operations, `--c1`); 11 at placement (P1a),
  4 past the bound (the tooth's skipped rule is the filter eviction uses too); canary seeds 35.
- `relabel_kept`: 25 of 40 seeds caught (100 operations, `--c1`, 5 s bound), 6 of them in 1..10
  (the tooth's range); canary seeds 50 (rate budgeted at 0.4).

## Traps

- The tidy 70-line limit caught `Cluster.init`; the tenant setup is `init_tenants`.
- Draw with a fixed width: `random.uintLessThan(usize, ...)` draws differently on wasm32, and the
  tenant world diverged between native and WASM until `relabel_node` drew u32.
- `create_node` gets its `Node` from `gpa.create`, which applies no field defaults: a new `Node`
  field must be set there (Debug fills it with 0xaa; `relabel_to` read as set to 170).
- Capacity: see above. Any new world feature that removes nodes from the service pool must be
  reflected in `replicas_for`.
