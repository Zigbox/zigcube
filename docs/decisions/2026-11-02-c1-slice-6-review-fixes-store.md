# C1 slice 6 review fixes

*Decided 2026-11-02.*

C1 slice 6 review fixes. **`Store.lease_grant`'s range check is approved** (owner): the wrapper asserts the grant is in range, not equal to the request. **No call waits past the fence:** the agent core sets the transport's deadline to `fence_at` through `Context.deadline` before the first call and again after a grant or keepalive moves it; a long poll holds at most until the fence (`Agent.watch_hold_ms`, used by the shell and the sim alike); a call starting with no time left fails at once (`ZC-E0503`); connect is a non-blocking connect polled to the call's end (Linux only). **A fence finishes:** `fence_step` reads the clock before each container, kills (grace 0) once `kill_at` has passed and goes on past a container's error; the fence and its `kill_at` are kept in `lease.json` (`fencing`, `kill_at_ms`), so an agent restarted mid-fence finishes it by the first kill time. **Restore fences** on any read error but `Absent`, a file it cannot parse, a send time in the future, another `boot_id` (`/proc/sys/kernel/random/boot_id`, kept with the lease) or a ttl it cannot fence under; the agent refuses such a granted ttl outright with `ZC-E0504`. Observed records carry the tenure on every write. **Known gaps:** (1) `Runtime.stop` blocks up to its grace (the approved contract, Ask first), so the fence cannot signal every container before waiting on one: `FakeRuntime` waits at most 500 ms per container and the fresh clock read keeps the kill from slipping past `kill_at` by more than one stop's wait; a non-blocking stop (or signal-all) is the owner's call. (2) The memory store numbers leases from 1 in each process, so after a server restart on `--store memory` a kept lease id can name another node's new lease; the tenure compare still refuses every write of the old agent, and the memory store is for tests and the console.
