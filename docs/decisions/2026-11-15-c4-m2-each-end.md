# sim-c4: M2 holds at each end, and against the store

Date: 2026-11-15. C4 fixups of #263 (Reviews A and B). This replaces the "Direct dials" reasoning
of `2026-11-15-c4-sim-c4-worlds.md` and the view-only M1 and M2 of slice 5. That file is merged
and stays as written.

- **M2 applies at each end that holds a connection.** The earlier note said an accepted direct
  dial is "counted, not kept", because the source's supervisor never held it and so M2 did not
  apply. That was wrong. The brief's M2 is a revoked grant's connections closed within
  `mesh_revoke_ms`, and the destination's supervisor holds every connection it accepted. A
  direct dial is now kept as a connection the destination alone holds (`Conn.source_held =
  false`). M2 is judged at the destination only, and the source's rules never close it.
- **The model closes on rules, the checks read views.** Each end that holds a connection closes it
  when its own rules drop the grant: the destination's accepts, or the source's listeners for that
  service and port. M1 and M2 still judge from each end's view at delivery, which is the record,
  not `mesh_plan`. So a compiler that hands a supervisor rules its view does not justify is caught.
  The new tooth `mesh_stale_accept` does exactly that: `rules_of` keeps every accept a replica
  was ever given. It must fail M1 (a stale accept takes a new connection) or M2 (a connection
  only the destination holds outlives its revocation).
- **A second bound, against the store's truth.** Judging each supervisor only against the view it
  was delivered could not catch an agent that stops delivering. With `agent_mesh.update`
  returning 0, sim-c4 passed 10 of 10 seeds (Review B). The model now reads the committed grants
  every tick (`observe`). A grant counts only when both services exist with a mesh address,
  because a grant naming a missing service opens nothing (ZC-W0704). After the heal, a connection
  on a grant the store no longer holds must close (M2), and must not be accepted (M1), within
  `truth_bound_ms` (`server_retry_ms_max + mesh_revoke_ms + 2 * agent_resync_ms`, 8 s: an agent cut off backs off for up to `server_retry_ms_max` and may still be waiting out that pause at the heal, seed 1 at 100 operations). The time counts from the
  latest of three moments:
  - the commit;
  - the heal;
  - the moment the earliest holding end's agent was again up and reachable.

  Before the heal there is no bound: an agent cut off from the server keeps its last rules. That
  is the gap sent to the owner (agent_mesh.zig, no staleness bound when the view read fails).
- **At rest (J10's style).** After convergence, every running mesh replica on a live node has a
  supervisor whose accepts are exactly the store's grants into its service.
- **The report.** It replaces the old "longest after a revocation" figure, which moved only under
  the tooth. It now gives the longest time from a grant's removal to the close, over the run and
  after the heal (against `truth_bound_ms`). It also gives the longest time past a view's delivery
  (against `mesh_revoke_ms`), plus routes to draining replicas, deliveries left unjudged past the
  model's 512 supervisors, and supervisors judged at rest.
- Keeping direct dials, and the extra span draw per accepted dial, changes the model's own draws.
  So a `--mesh`, `--c4` or `auto` world drawn before this change is a different world. Worlds
  without the mesh are unchanged.
