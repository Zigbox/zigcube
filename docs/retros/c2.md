# C2 retro

C2 shipped peer-to-peer image fetch: content-addressed chunks, peer bundles, a strike list for lying peers, locality-aware scheduling, and registry-once pulls. The release review gate (two independent reviews) found four MUSTs that every slice review had passed.

## What was off

- **"Slice 8 passes as cube" while O5 was unbuilt.** We deferred the registry-once election (O5) behind a decision, and the demo was written to record the miss. The first green-looking path hid that the decided behaviour did not exist. Cost: one red demo-c2 run, a review MUST, about two hours. Change: a decided behaviour that a demo asserts is built in the slice that writes the assertion, or the slice is not done.
- **Every peer socket was assumed to be fast.** The peer server's reads and writes had no deadline, and the per-source limits did not count NAT'd peers. Slice review passed it; the release review found it. Change: REVIEW.md now requires a deadline on every socket read and write.
- **The fetch was assumed to be one process.** The deadline killed the waiter's pid and left its store worker writing. Change: a child that starts children runs in its own process group and is killed and reaped as one (REVIEW.md).
- **The serving store was assumed to have one writer.** Each peer-server slot cached "already walked" and never noticed trees that the supervisor's pull added. Steps 2 and 3 of demo-c2 failed silently, as refusals that looked like busy peers. Change: a cache over a store other processes write re-checks on a miss (REVIEW.md), and every ZC-E0601 now lists per-peer busy, refused and unanswered counts, so the next such failure names its cause.
- **Borrowed strings outlived their buffer.** parse_page kept slices into a poll buffer that the next poll overwrote, so no node was ever designated. A unit test now covers it.

## What worked

- Two independent release reviewers found disjoint MUSTs (three and one). Keep two.
- The demo recorded misses and kept going, so one run gave the evidence for every failing step.
