# B1 retro

B1 shipped jobs: run-to-completion work with a deadline, claim-then-start, cancel, endings, retention and `demo-b1`. The two release reviews found three MUSTs that every slice review had passed; #148 and #150 fixed them.

## What was off

- **J8's bound needed a term for cut links.** We assumed the agent "can't stop a run it can't report". Wrong: the bound hid that the agent did not enforce deadlines offline at all. Release review MUST 1 found it; #150 cost a fix-and-re-review cycle of about half a day. Change: a check's bound gets no term for an outage unless a decision says why, and every tooth gets a positive run of its world with the fix on (`sim-c1-offline` is the first).
- **Moving work before the heartbeat was assumed free.** The first #150 version let one run's failing write fence the whole node; the review caught it with a probe test. Change: anything added before the heartbeat contains its own failures, and a test proves the lease survives it.
- **demo-b1's ordering was assumed deterministic.** A race made it flaky on main until #149. Cost: re-runs and a delay.
- **`job-observed` was assumed to fit in one response.** #148 paged it. Upgrade servers before agents.
- **One demo-c1 sqlite failure on a #150 commit** (node3 saw the loss at 13.6 s, expected under 10.3 s) did not reproduce locally in 7 runs and passed on the next commit. Recorded as a probable runner stall; tracked for B2.

## Soak and what moves to B2

The owner waived the 24-hour fleet soak for B1 (`docs/decisions/2026-11-07-b1-ships-without-fleet-soak.md`). Fleet findings and the release reviews' SHOULDs and NITs go to B2, the hardening release.
