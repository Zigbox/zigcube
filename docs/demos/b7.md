# B7: the API over mTLS

## demo-b7 (slice 4)

`zig build demo-b7 [-Dtranscript=FILE]` (`src/demo_b7.zig`, `src/demo_b7_steps.zig`) runs on
the host with no KVM: `zcube-server` on SQLite with `--listen` (TLS 1.3, every client presents a
certificate of the store's CA) and `--insecure-listen` (loopback), one `zcube-agent` with
`FakeRuntime`, and the `zcube` command. The demo acts only through the TLS listener; it reads what
happened through the insecure one, as the other demos do. About 15 s.

0. The server makes its CA (`server-state/ca-<hash>.crt`). The operator runs
   `zcube-server ca issue-client app --scope jobs`, `zcube-server ca issue-client ops --scope
   admin` and `zcube-server ca issue-node node1`; each must exit 0 within 60 s. `ZCUBE_CA`, `ZCUBE_CERT` and `ZCUBE_KEY` name the CA and the `app` certificate.
1. node1's agent starts with `--ca`, `--cert certs/node1.crt` and `--key certs/node1.key` and
   joins over TLS: `/nodes/node1` appears in the store and the agent writes its own
   `state/node.crt`.
2. The `jobs` client runs `zcube job run hello ... sleep 300`; the job reaches `running`;
   `zcube job cancel hello` succeeds; `zcube job get hello --wait` exits 12 with `end: cancelled`.
3. The same client is refused services: `zcube apply --yes web.zon` fails with ZC-E0822, and a
   `POST /v1/services` by hand with the same certificate is 403 with ZC-E0822 in the body;
   no `/services/web` is in the store (`GET /v1/list?prefix=/services/` on the insecure listener).
4. A TLS 1.3 client that pins the CA and answers the server's certificate request with no
   certificate gets no answer to `GET /v1/jobs` (the client reports ZC-E0814), and the server's
   log gains `tls: ZC-E0814: the client sent no certificate`.
5. With node1's own `state/node.crt` and `state/peer.key`, `POST /v1/agent/nodes/node2/lease` is
   403 with ZC-E0822, `GET /v1/agent/nodes/node1/replicas` is 200, and no `/nodes/node2` exists.
6. With the `ops` (admin) certificate, `GET /v1/codes` is 200 and its body, longer than one TLS
   record (16 KiB), arrives whole: its length equals `Content-Length` (review MUST 1 of slice 4,
   the TLS writer's drain that spun on a reply longer than its buffer).

Every process started is killed at the end, and the demo checks that none is left.

Cuts: node readiness is read as `/nodes/node1` in the store (`GET /v1/list` on the insecure
listener), not `zcube get nodes`, which the `jobs` client may not call. The demo runs on SQLite
only: the listener and the scope checks are above the store, and demo-c0, demo-c1 and demo-b1
cover Postgres.

Run: `zig build demo-b7` passed in the cloud container on the slice's commit. It is not a passed
demo until CI's `demos (sqlite)` job runs it green.
