# C4 demo: the service mesh

The demo itself (`zig build demo-c4`) arrives with C4's last slice; `docs/briefs/c4.md`, "Demo",
says what it will assert. This file records the milestone's cuts as they are made.

## Cuts

- **Service certificates are asked for only by the simulator's supervisor (C4 slice 3,
  approved by the supervisor, docs/decisions/2026-11-14-c4-service-cert-rulings.md, ruling 5).**
  The server issues them (`POST /v1/agent/nodes/{node}/replicas/{id}/certificate`), but
  `zcube-agent` and the real supervisor make no key and ask for none yet. Renewal at half-life and
  ZC-W0703 (a certificate that expired unrenewed takes the replica off the mesh) live only in the
  simulator's model of the supervisor (`sim_mesh_certs.supervise`); M3, M3r and M6 check that
  model and the issuer it calls (`service_cert.look_up`, `service_cert.decide`, shared with the
  server). The slice that adds the real supervisor's ask must put it under the simulation.
- **No admission warning for a short image pin (C4 slice 3, ruling 2).** A service pinned by a
  short `b3:` digest is admitted and then refused every certificate (ZC-E0706, "pin the full
  64-hex digest"). A warning at `zcube apply` is a follow-up; the rule itself awaits the owner's
  sign-off.
- **No mesh trust in `/service/` certificates before B7 (ruling 6).** Issuance is unauthenticated
  (docs/mtls.md, "Issuance"), so the mesh must not accept these certificates as proof of a
  replica outside a test cluster on a private network until B7.
