# B3: relays (slice 2 notes)

The B3 demo itself arrives with its last slice. This file records what slice 2 (the relay over
the fake runtime, #208) cut or deferred, so the owner can see it.

## Cuts and deferrals

- **ZC-E0701 is not shown in `zcube why job` yet.** The brief wants an unreachable upstream in
  `why job`; slice 2 writes the coded line to `relay.log` in the container's directory only
  (first lines, at most `relay_log_bytes_max`). Where it lands: the slice that makes the agent
  report relay trouble in a job's ending (needs a field on the run record and the job API,
  which is an API change, so it is not done here). `relay.zig`'s header says the same.
- **A hostname or IPv6 upstream can delay the supervisor's ending by up to
  `relay_connect_timeout_ms` (10 s).** The IPv4 literal path connects in `relay_poll_ms` slices
  and honours `stop`; the name and IPv6 paths go through `std.Io` and block until that timeout.
  Consequence: a job that ends while a connection to a black-holed named upstream is connecting
  records `run.json` up to 10 s late (`kill_and_wait` may report "not ended" first). The DNS
  lookup's own use of the timeout is not tested. Left as is because resolving at `open` would
  put the same block in front of the job's start; the fix (a stop-aware resolver) is B4's, with
  mTLS, which replaces `connect_upstream`.
- **`sim_runtime` ignores `spec.relay`**, against the field's doc comment. Harmless until slice 3
  makes simulated jobs relayed; it refuses or models the relay there.
- The `Runtime.Spec.relay` ask is recorded in
  `docs/decisions/2026-11-10-runtime-spec-relay.md`.

## Review fixes made

ZC-E0702 has its own blame (`run.json` `blame: "relay"`), so a relay that cannot be set up is
E0702 with the failed step in its cause, not E0507. The server's relay-address check refuses
`[]:80`. The three bounds live in `relay.Limits` (never above the constants) and each exit path
has a test (idle, bytes, connect timeout). A failing `accept` is logged once and backs off. A
local socket failure is E0705, not the upstream's E0701. The relay test writes `relay.env`
by rename. The lanes fuzzer drives the real `round` over fake sockets (short counts, would-block)
and fails with an end passed to the wrong socket.
