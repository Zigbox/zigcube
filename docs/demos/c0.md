# C0 demo: what is demonstrated, and what is not

**`demo-c0` does not exist yet.** It needs `zcube-server`, `zcube-agent`, the `zcube` command,
`FakeRuntime` and the Postgres and SQLite wiring, none of which is built. Nothing here has passed
the demo.

## What exists in its place (C0 slice 5a)

`zig build sim-c0` is a deterministic **simulation** of the demo's steps against the core, a memory
store and a simulated runtime on virtual time ([core.md](core.md) says what it proves). It is
not the demo and is never reported as one.

| Demo step | In the simulation |
| --- | --- |
| 1. apply `hello`, 3 running | asserted |
| 2. `kill -9` one, replacement | asserted (a runtime fault, not a host process) |
| 3. scale to 5, back to 2 | asserted; the three that ran stay when scaling up |
| 4. `broken`, `zcube why service broken` | asserted, including the rendered chain |
| 5. store down, `zcube get`, `zcube bundle --last` | the API's answer with the store down is asserted (503, `ZC-E0201`, a fix); the CLI and the bundle do not exist |
| restart server / agent mid-run | asserted: nothing duplicated, nothing lost |

## Cuts recorded

- The chain's middle line is api.md's sentence ("replica broken-1 failed to start on node1; it
  was not replaced because a new one would fail the same way"), not HANDOFF's "pending on node1";
  api.md wins where they differ.
- The diagnostic's digest is shortened with `...`, not `…`, and its fix says "the service file",
  not "broken.zon": diagnostics are printable ASCII, and the runtime does not know the file name.
