# B2.1: B2's follow-ups

**Status: brief, 2026-11-09. Not started.** B2.1 follows B2 (release PR #200, candidate `e1e9bc0`,
tag `b2` pending its 24-hour fleet run). It is named B2.1, not B3, because B3 is the Botpike relay
([../decisions/2026-11-09-b2-1-follow-ups-not-b3.md](../decisions/2026-11-09-b2-1-follow-ups-not-b3.md)).

**Nothing in B2.1 merges to `main` before the `b2` tag.** The fleet follows `main`'s tip, so a merge
restarts B2's clock. Implementers work on their own branches and open pull requests; the
supervisor merges them, in slice order, once `b2` is tagged.

Sources: issue #205, both B2 release reviews on #200, and
[../decisions/2026-11-09-b2-ships-without-job-reuse.md](../decisions/2026-11-09-b2-ships-without-job-reuse.md).
**RA** is release review A,
[#200 review 5821706336](https://github.com/Zigbox/zigcube/pull/200#pullrequestreview-5821706336).
**RB** is release review B,
[#200 review 5821754451](https://github.com/Zigbox/zigcube/pull/200#pullrequestreview-5821754451).
`#N` is `https://github.com/Zigbox/zigcube/issues/N` (or `/pull/N`). This brief was written from
#205 and a reading of the code at `e1e9bc0`; nothing was built or run for it.

## Goal

Close what B2 shipped without, so the next feature release (B3, the relay) starts from a tree
whose teeth, CI and tests can be trusted:

1. CI's simulation job has room for the teeth B2.1 adds.
2. No test in `zig build test` is known to be flaky.
3. Every job check either runs or fails the run; none skips silently.
4. Each RB-N8 tooth (`job_reuse`, `job_evicted`) exists and runs over a seed range sized from a
   measured hit rate.
5. Every SHOULD and NIT left open by RA and RB is fixed or dropped with a written reason.

B2.1 adds no feature. A user-visible change is a fix to documented behaviour, or is asked first.

## Non-goals

- **The Botpike sequence** (B3 to B7): the relay, identity, signed images, placement by tenant, API
  identity.
- **The Jepsen battery** (a C5 prerequisite). The gate clause for it stays vacuous.
- **New bounds, defaults or codes** unless asked first (AGENTS.md). `ledger_max`, `jobs_max` and
  the admission window stay as they are unless slice 3 asks.
- **More seeds in CI for their own sake.** Slice 1 makes room; it does not fill it.

slice first.

and run one after another. Slices 2 and 6 run beside anything. With one implementer at a time
beside M8: 1, 2, 3, 4, 5, 6 in that order.
