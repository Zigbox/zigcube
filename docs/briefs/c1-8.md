# C1 slice 8 · `demo-c1`: HANDOFF's C1 demo, run for real

*Written 2026-11-03 by the implementer from HANDOFF's C1 demo script, item 8 of [c1.md](c1.md) and
the `demo-c0` harness (`src/demo_c0*.zig`, [docs/demos/c0.md](../demos/c0.md)). There was no
separate brief; this is it.*

## Goal

`zig build demo-c1 -Dbackend=sqlite|postgres [-Dtranscript=FILE]` starts the processes a fleet runs
(`zcube-server`, three `zcube-agent`s with `FakeRuntime`, the `zcube` command), drives them as a
person would, asserts every outcome HANDOFF's C1 section names, and prints a transcript. Nothing is
simulated. Each step also becomes a section of [docs/demos/c1.md](../demos/c1.md), which says what
is and is not asserted. A CI job per backend runs it, modelled on `demo-c0`'s. A local pass is a
check; the demo counts only when its CI job is green.

## The script

| # | Step | Source | What it asserts |
| --- | --- | --- | --- |
| 0 | Start | demo-c0 | server on the backend, `--lease-ttl-ms 8000` (the lease timeout is configurable); three agents `node1..node3`, separate state directories under the run's directory, `node1` reaching the server through a fault proxy |
| 1 | Three agents join | HANDOFF 1 | `zcube get nodes` lists `node1..node3`, `ready`, with capacity `4000m / 8.0Gi` and a lease of `/8s` |
| 2 | `hello`, 6 replicas | HANDOFF 2 | 6 running; `get replicas -o wide` shows two per node; the host runs 6 commands under 6 supervisors, two per agent's state directory, each supervisor a child of its node's agent |
| 3 | Power off `node3` | HANDOFF 3 | `kill -9` of the agent and of its supervisors' groups; its 2 replicas are replaced on the survivors under new ids (owner decision) within `ttl + lost_grace_ms` plus the scheduler's pass; the node reads `lost`; `hello` is 6/6 again; the survivors' original 4 commands are the same processes; the `mark_lost` decision carries the ttl (8 s) and the time last heard, and `zcube why node node3` prints both ("printed at failover") |
| 4 | Restart `node3` | HANDOFF 4 | the agent rejoins empty (a new tenure, no containers, none assigned); nothing moved back (no rebalancing); `zcube why node node3` explains it (the note: ready, fewer replicas than another node, nothing is moved back) |
| 5 | Partition `node1` | c1.md "The partition test" | the proxy drops both directions; the agent stays alive; stops its containers before `P + ttl − fence_margin + fence_stop + kill latency` (`P` the partition's start, an upper bound on `s`); the replacements start no earlier than the server's expiry (read from `GET /v1/leases` after the partition) plus `lost_grace_ms`; no instant at which an old command and a replacement of the same service ran at once (polled every 20 ms); after the heal the agent re-registers under a new tenure, empty, prints `ZC-W0501`; a late observed write under the old tenure is refused (`503`, `ZC-E0510`, I2) |
| 6 | Local mode | c1.md "Local mode" | on copies of the executables in a scratch directory, `zcube local up` starts a server on SQLite and an agent; `zcube apply` of `hello.zon` reaches 3/3 running; `zcube local down` stops both, containers left running are stopped by the demo |

## What is reused

`demo_host.zig` (the server, the CLI, the transcript, `wait_for`, API reads, `free_port`),
`host_procs.zig` (the host's view of supervisors and commands, one `Procs` per node),
`testing/fault_proxy.zig` (the partition), `demo_c0_decisions.zig` for the decisions read. New:
`demo_c1.zig` (options, main, script), `demo_c1_fleet.zig` (three agents, kill and restart, host
facts), `demo_c1_steps.zig` (steps 1–4), `demo_c1_partition.zig` (step 5), `demo_c1_local.zig`
(step 6). `demo_host.Config` gains `lease_ttl_ms`.

## Decided here (flag any you disagree with)

1. **Lease ttl 8 s, `lost_grace_ms` the default 1 s.** The ttl is passed on the server's command
   line, which shows the configuration works and shortens the run; the inequality of authority.md §3
   holds (3 s margin ≥ 2 s + 80 ms skew + 0.9 s).
2. **Only `node1` is behind the proxy.** The other agents talk to the server directly. `node3` is
   the one powered off and restarted (HANDOFF names it); the partition takes `node1` after the
   cluster has settled, so `node3` is empty-and-ready and can receive its replicas.
3. **Bounds from the host.** The agent's `s` is not observable; `P ≥ s` makes the stop bound weaker
   but sound. The server's expiry is read after the partition has taken hold (200 ms later), when no
   more keepalives can land. The comparison tolerates 250 ms for the poll and the clock reads.
4. **"Power off" is `kill -9` of the agent and of every supervisor group under its state directory**
   (`demo/kill-node.sh`, in Zig).
5. **Not repeated from C0:** server and agent restarts, the broken digest, the store outage.
   `demo-c0` still covers them and still runs.
6. **Out of scope** (HANDOFF/c1.md): a second server, rebalancing, Postgres outage in C1 (slice 10).
