# C1 slice 9 · The simulation fleet

*Cut from `docs/briefs/c1.md` (slice 9 and "Gate for shipping C1"). Read `AGENTS.md` and `docs/STYLE.md` first. Where this and c1.md disagree, c1.md wins: stop and report.*

## Goal

C1 ships only when a host runs `sim-cluster-exe` around the clock on fresh seeds at the tip of `main`, files every new failure, and says every day how many seeds it ran, so silence is not mistaken for health. This slice builds that runner and its deployment. It does not deploy it: the owner provides the host and the token.

## What to build

- **`sim_fleet`** (`src/sim_fleet*.zig`, Zig standard library only; `std.http.Client` does TLS). `sim_fleet ingest` reads the output of `sim_cluster --seeds A..B <ops> --shrink` on stdin and, for each failing seed, files or comments on GitHub (`Zigbox/zigcube`).
- **Fingerprint** = the failing check (the `FAILED:` text) plus the step where it fails (`faults`, `healed`, `convergence` or `end`: a new `step:` line in `sim_cluster`'s report and range output). Not the seed, the commit or the operation count, so it is stable across commits. A hash of `kind`, check and step.
- **Filing.** A fingerprint not yet filed becomes an issue: the commit, seed, shrunk `ops`, the one-line replay command, and a hidden marker holding the fingerprint. A fingerprint already filed gets a comment (one per fingerprint per run of `ingest`; further seeds of the same batch are listed in it), not a new issue. Filed fingerprints live in a state file; if the file is lost, the markers on the issues rebuild it.
- **Seeds per day.** The state file counts seeds, failures and batches per UTC day. The first `ingest` of a new day comments the previous day's totals on one tracking issue (`--tracker N`). A missing comment is the alarm.
- **`--dry-run`** prints what would be filed and commented and changes nothing on GitHub. The GitHub client sits behind an interface with a fake for tests.
- **A hook for `test-store-faults`** (once a day, later): `--kind` names the producer; only `sim-cluster` is built, any other kind is refused.
- **`ops/sim-fleet/`**: a systemd unit, `setup.sh` for a fresh Ubuntu 24.04 host (pinned Zig, clone, build, an unprivileged user), `run.sh` (the loop: fetch `main`, rebuild when it moved, run a batch, `ingest`), and a README that says how to deploy and how to make the token (a fine-grained PAT, Issues read/write on `Zigbox/zigcube` only, read from a file, never logged).

## Tests

Unit: fingerprint stability (same check and step, different seed and commit, same key; different step, different key), parsing of the runner's output, issue and comment rendering, the state file round trip, the day report, and the whole `ingest` against the fake client (one issue, then comments; a lost state file rebuilt from markers). Teeth: `sim-teeth-exe` output fed to `ingest --dry-run` twice shows one would-be issue and then one would-be comment.

## Done when

`zig build check` passes on the pushed commit; the teeth dry-run output is in the report; `ops/sim-fleet/README.md` says how to deploy.

## Non-goals

Deploying; creating a token; running `test-store-faults` (only the hook); a dashboard; alerting beyond the daily comment; any dependency beyond the Zig toolchain.
