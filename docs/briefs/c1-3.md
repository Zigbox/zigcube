## Goal

Placement leaves the replica controller and `/replicas`. A scheduler, the sole writer of `/assigned` and `/allocations`, places, releases and moves replicas with the full compare set, keeps each node's allocation record exact, and holds a replica that fits nowhere with the shortfall as evidence. On one node, `demo-c0`, `agent-smoke` and `sim-c0` behave as before: the same replicas end up running, with placement decisions now made by the scheduler.

## What to build

1. **The scheduler** (`src/scheduler.zig`, core, in `src/core.zig`'s list; role `scheduler`).
   - **Reads:** `/replicas`, `/assigned`, `/nodes`, `/node-status`, `/allocations`, `/audit/allocations`. Only nodes whose `/node-status` is `ready` *for the tenure of their current `/nodes` record* are candidates (I7).
   - **Fit:** the replica's resolved `requests` (`requests_of`, moved from `replica_controller.zig`) plus the node's `/allocations` total stay within its declared capacity, on CPU and memory. A node with an open `/audit/allocations` finding, or whose allocation record is over its capacity, is excluded.
   - **Spread:** fewest assignments of the same service, then least allocated (CPU, then memory, as a fraction of capacity), then node name. Deterministic.
   - **Place** (an unassigned replica): one transaction putting `/assigned/<n>/<r>` and the new `/allocations/<n>`, with the `place_replica` decision, compared with `compare_sets.placement` (6). The first placement on a node creates its allocation record (compared absent).
   - **Release** (an assignment whose `/replicas` record is gone): delete `/assigned/<n>/<r>`, subtract from `/allocations/<n>`, `release_replica` decision, compared with `compare_sets.release` (2).
   - **Move**: release on the old node and place on the new in one transaction with `compare_sets.move` (8). Slice 3 builds and tests it; nothing in C1 triggers one until slice 4 (a lost node).
   - **Hold** (no node fits): nothing is assigned, `/replicas` untouched, one `hold_pending` decision per change in the reason, with the shortfall as `cause_evidence` (per node: the resource that fails and by how much, or why it is excluded). `c1.md`'s "A replica that fits no node" row is the rule; the scheduler retries on any change to the keys it reads, never on a timer.
   - **A failed compare** means the world changed: plan again from the new state, never retry the same transaction.
   - Keep `batch_places_max` and the run budget the replica controller has today.
2. **`node` and `requests` leave `/replicas`.** `Replica` drops both fields and is written as `"v": 2`; a v1 record still reads (the C0 fixtures from slice 2 must pass) and its `node` is ignored. The replica controller no longer schedules (`place_unplaced`, `place`, `choose_node`, `load_of` go), never reads `/assigned` to decide anything, and reads it only to report. Every reader of a replica's node (`grep -rn 'rec\.node'`: the agent endpoint, `why`, `cli_get`, `cli_view`, the sims, the demo checks) reads `/assigned` instead.
   - **The agent endpoint** serves an agent the same shape as today, built from `/assigned/<node>/` joined with each `/replicas` record. An assignment whose replica is gone is not served (so the agent stops it). The dedicated per-node long-poll and `bench-watch` are slice 7; here the endpoint may wake on either prefix.
   - **No in-place upgrade from a C0 store.** A v1 replica's `node` is ignored and the scheduler places it again; on one node that is the same node, and the agent adopts the running process by replica id. Record this in `docs/DECISIONS.md`.
3. **`next_replica` gets its own key** (owner, 2026-10-30; DECISIONS.md). `/replica-numbers/<service>`, written only by the replica controller: `{ "v": 1, "next": N }`. The transaction that creates replicas compares it at the revision read and puts the new value. `Service` drops `next_replica` (`"v": 2`) and `apply.zig` stops writing it. The first counter for a service is the larger of a v1 service record's `next_replica` (read for this purpose only) and one past the highest replica number in `/replicas`, so a number is never reused. The key is never deleted: it is kept after the service and its replicas are gone (one small key per service name ever applied), so a re-apply continues the numbering and replica ids are unique forever. The seed rule applies only when the key is absent. Remove `api_with_counter` from `writers.zig`; `/services/` is then the API's alone, and the writer-table test says so.
4. **A minimal node controller** (role `node_controller`, core). Without one nothing is `ready`, so nothing places. Slice 3 writes only this: a node with a `/nodes` record and no `/node-status`, or a status for an older tenure, gets `ready` with the current tenure (the `/nodes` record's `mod_revision`, the tenure revision of `authority.md` §3) and a `mark_ready` decision. If C0's agent rewrites `/nodes/<node>` after registering, each rewrite is a new tenure and would churn readiness and fail placements: check, and if it does, report it rather than work around it (slice 6 makes the lease the keepalive). Lease expiry, `lost`, `fenced` and the auditor are slice 4.
5. **Wiring.** The server's controller loop and both simulations (`sim_world.zig`, `sim_c0.zig`) run the scheduler and the node controller beside the replica controller. `docs/keys.md` marks `/assigned`, `/allocations`, `/node-status` and `/replica-numbers` as written from slice 3.

## Tests

- **Scheduler units:** fit on CPU and on memory, each failing alone; the spread order's three tie-breaks; an excluded node for each reason (not ready, older tenure, open audit, over capacity); a hold whose evidence names every node and stays within `decision_evidence_bytes_max` with `nodes_max` nodes; one `hold_pending` per change in the reason, not per pass.
- **Conformance, all three backends:** a place, a release and a move committed by the scheduler code (not the bare builders), each refused when one compared key moved; the phantom case through the scheduler: two scheduler instances plan on the same allocation revision, one commits, the other writes nothing and places correctly on its next pass.
- **I6 as a check:** after every scheduler pass in the tests and in `sim-c0`, `sum(requests of /assigned/<n>/*) = /allocations/<n>.allocated` and the counts agree, for every node.
- **Counter:** numbers never reused across scale down, scale up, delete and re-apply; a C0 service record's `next_replica` is honoured; the replica controller's transaction fails when the counter moved.
- **No behaviour change on one node:** `sim-c0` passes (its report may change because decisions changed: say how), the C0 why/snapshot tests pass, and every changed golden is named in the report with the reason.
