## Before you write code: check that you can build

If `curl` returns an error page rather than a gzip file, call `add_repo` for `Zigbox/zigbox` with read access and get the commit through git (`git archive` of that commit, unpacked the same way). **If neither works, stop and report before writing any code.** Run `zig build check` once on the untouched branch and keep its last line.

## Why

`sim-c0` already shows the method works: virtual time, one seed, faults under test control, invariants, native and WASM agreeing byte for byte. But it runs one agent, talks to the store directly, and leaves the agent's loop, its client half of the agent endpoints, and its persisted state in the shell, where no seed reaches them. C1 is about a fleet: partitions, lost acknowledgements, agents that crash and restart, clocks that disagree. Those are the bugs that corrupt orchestrators, and slices 3 to 6 (scheduler, node controller, sim-c1, agent fencing) should be written against a simulator that can produce them, not have one bolted on after.

## Goal

One simulator runs the whole cluster from one seed: the server's controllers, N agents each with its own runtime, clock and persisted state, the store, and a network between agents and server that carries the real agent-endpoint bytes. Faults hit every layer. Each seed also chooses its own fault rates, node count and workload mix (swarm testing). A liveness mode heals everything at a set time and requires convergence. On one agent with no faults, the outcomes `sim-c0` asserts are unchanged.

## What to build

1. **The agent's remaining logic moves into the core**, so the simulator runs the code production runs.
   - `agent_run.zig`'s loop policy (step, wait, back off, report a failure once, stop) becomes a core state machine, `agent_loop.zig`, driven by `Clock` and events. `agent_run.zig` keeps only the process, the signal and the real wait.
   - `agent_remote.zig` splits: building requests and reading responses for the agent endpoints (core, `agent_client.zig`), and the transport (shell, unchanged behaviour over `agent_http.zig`).
   - What the agent persists goes through an `AgentState` interface in the core. The shell's implementation is today's files (`fake_files.zig`). The simulator's models what those files actually guarantee: a write that is renamed into place lands whole or not at all; anything appended can lose its tail in a crash. Read `fake_files.zig` and model what it does, not what it should do; report any write that is not crash-safe.
   - Add each new module to `src/core.zig`'s list. `wasm-check` and `wasm-test` must pass.
2. **A `Network` seam** between an agent and the server, carrying request and response bytes (the same bytes `agent_api.zig` takes and gives). The real side is the existing HTTP transport. `sim_net.zig` (core) adds, per link and per direction: drop, delay, duplicate, reorder, one-way partition, heal. **A response dropped after the server committed the request** is the case to make common, not rare: the agent sees a failure for a write that happened.
3. **A clock per node.** Each agent has its own simulated monotonic clock with a bounded rate error (the skew in `c1.md`'s fencing constants) and an offset from the server's. Monotonic clocks never go backwards; model `CLOCK_BOOTTIME`, which keeps counting while suspended, so a node can also jump forward (a suspend). The bound is a parameter: slice 5's negative tests will break it on purpose.
4. **Agents crash and restart** at any step boundary chosen by the seed: memory gone, `AgentState` as the crash left it, containers still running under their supervisors in that node's `sim_runtime` (as on a real host). A restart adopts by replica id, as the real agent does.
5. **The store's faults gain the lost acknowledgement**: a transaction that commits and returns an error to the caller. Check whether the memory store's fault hooks already allow it; add it if not, and say which.
6. **`sim_cluster.zig`** (core): the world. The server runs the controllers `sim_world.zig` runs today (slice 3 adds the scheduler and node controller here). Up to `nodes_max` nodes, each an agent, a runtime, a clock and a state. A workload generator: apply, scale, delete, a broken image, runtime faults, agent crashes, network faults, store outages. Leave `sim_world.zig` and `sim_c0.zig` alone so `sim-c0`'s report stays byte-for-byte identical; share code by extracting it, not by changing their behaviour.
7. **Swarm.** The seed picks the node count, each fault's rate (including zero), and the workload mix, and the run prints them first, so a report says what world it ran in.
8. **Checkers.**
   - **Safety, after every step:** `sim-c0`'s invariants, generalised to N nodes; and every decision has a cause that exists (as now).
   - **Duplicates are counted, not failed.** Without leases and fencing (slice 6), a partition can leave a replica running on two nodes. Count replica-seconds of duplicates and report them; slice 6 turns the counter into a failure. Say so in the report, so nobody mistakes the number for a pass.
   - **Liveness mode:** faults until a heal time chosen by the seed, then every fault off; within a bound after the heal, every service has the replicas it asked for and no node runs anything else.
   - **Determinism:** each run's report ends with a hash of the whole store and every node's runtime; running the same seed twice gives the same hash, and the native and WASM builds give the same report, as `sim-c0` does.
9. **Teeth.** A test-only fault in the agent (it ignores stop orders, or it forgets to persist one adoption; pick one and make it a comptime option that release builds cannot reach) must be caught by the cluster simulator within a stated number of seeds. A simulator that never fails proves nothing.
10. **Commands.**
    - `zig build sim-cluster [-Dseed=N] [-Dops=N] [-Dnodes=N] [-Dliveness=true]`: native and WASM, compare reports, like `sim-c0`.
    - `zig build sim-cluster-exe` installs the native runner. It takes a seed range, prints one line per failing seed with its replay command, and can shrink a failure by bisecting `ops` to the smallest failing count.
    - `zig build check` runs one `sim-cluster` seed with a fresh seed and a small `ops`, printing the seed first, as it does for `sim-c0`. Keep the whole `check` under its current wall time plus 60 s; say how long it takes.
11. **Docs.** `docs/core.md` gets a section, "The cluster simulation": what it proves, what it does not (real processes, real Postgres, the real `zbx`, and anything the models leave out), the fault list, the seed and shrink commands. `docs/agent.md`'s table says which pieces moved into the core. Lasting decisions go in `docs/DECISIONS.md`.

## Not in this slice

The scheduler and node controller (slice 3; they get wired into `sim_cluster.zig` there), leases and fencing (slice 6), the invariants I1a to I7 and their negative tests (slice 5), a fleet running seeds or a hub filing issues, a Postgres fault proxy, a conformance suite for `Runtime`, and any change to `demo-c0` or `agent-smoke` behaviour.

## Tests

- `agent_loop.zig` reproduces `agent_run.zig`'s behaviour today: back-off timings, a failure reported once, stop. Unit tests on virtual time.
- `sim_net.zig`: each fault alone, a partition and its heal, duplicate delivery of a write, and a response lost after commit.
- `AgentState`: a crash at every write point of an adoption leaves a state the restart can read.
- `sim-c0` report unchanged byte for byte; `agent-smoke` and `demo-c0` behave the same (CI runs them; say if you could not).
- The teeth test, and 1,000 `sim-cluster` seeds through `sim-cluster-exe` with no failure other than the counted duplicates. Report the seed range and the wall time.
