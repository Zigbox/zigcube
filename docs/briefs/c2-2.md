## Goal

A service names the OCI reference its image is pulled from, beside the tree digest it must unpack
to. The reference travels through `/services`, `/replicas` and `Runtime.Spec` to the supervisor,
which pulls from it when the tree is not in the node's store. Slice 1's node-local `--images` file
is no longer needed for that. It stays as a deprecated fallback for one milestone, so that a node
configured for slice 1 keeps working. The fake and sim runtimes ignore the new field, so every test
and demo keeps passing unchanged. `demo-c0` output must not change.

## Settled here

| Topic | Decision | Why |
|---|---|---|
| Name | `source`, as DECISIONS' P1 names it. The unwritten provenance reservation in keys.md and api.md item 4 is renamed `provenance` (git commit, file digest), still reserved and not written. | No stored value has either name today, so nothing on disk changes. **Owner to confirm**; if the owner wants the reverse, it is a rename within this slice. |
| Shape | An optional string, default `""`. Empty means "no reference: the tree must already be on the node, or in its `--images` file". | Additive, so old records and old service files read. |
| What `apply` accepts | Empty, or 1–1024 bytes (Zigbox's `reference_bytes_max`; a Zigcube constant `source_bytes_max` with that derivation in its comment), with **no whitespace or control characters**, and ending in `@sha256:` followed by exactly 64 lowercase hex digits. Anything else is ZC-E0104 with a sentence that says which rule failed. | A tag can move under the lock. A digest pin cannot, so the lock check (ZC-E0511) only catches platform or lock mistakes. The check is a narrow, pure function in `apply.zig`, so the core stays wasm-clean; the core cannot link Zigbox's parser. |
| Full parse | The supervisor parses with `pull.parse_reference` before pulling. A reference that passes apply's check but fails Zigbox's parse is `start_failed` with Zigbox's diagnostic, unchanged. | One parser of record. Apply's check is a prefilter that catches the common mistakes at apply time. |
| Generation | A change of `source` **bumps `generation`**, like `image`. The "what changed" line reads `source a → b`, shortened like `image`. **Owner to confirm.** | A replica held on a node by ZC-E0511 (wrong tree) or a pull failure is replaced only on a generation bump. Fixing a bad reference must therefore move the generation, or the fix never reaches the node. The cost is one replacement of every replica when only the reference changes and the tree does not. That is rare, and the tree is already on the node, so no pull. |
| Versions | `Service` v3, `Replica` v3. Both read v1 and v2 (default `""`). v4 is ZC-E0303. | REVIEW.md: the version moves with the shape. |
| `Runtime.Spec` | Gains `source: []const u8 = ""`. `spec_problem` gains `.bad_source` when it is longer than `source_bytes_max`. No other check: the spec is built from a validated replica. | This is the approved P1 contract change, and the only one. The `Runtime` vtable is unchanged. |
| Fake and sim | `FakeRuntime` and `SimRuntime` ignore `source`. `fixtures/images.zon` is unchanged. | The C0 demo and every sim report stay byte-identical, and the sims' digests are compared native against WASM. |
| ZigboxRuntime | `reference = if (spec.source.len > 0) spec.source else self.reference_of(spec.image)`. The `--images` file is now deprecated for `--runtime zigbox`: when it is given, the agent logs one line at start (`--images is deprecated: put source in the service file`). It is removed in C3. | A node configured for slice 1 keeps working, and nothing on the node holds intent once services carry `source`. |
| API and console | `source` appears in the apply body, in `GET /v1/services` and `/v1/services/<name>`, and on replicas, as an optional string. The mock copies and compares it like `image`. The console shows it where it shows `image`, under the same "shortened, full on hover" rule (docs/console.md first). | It is not a secret, unlike `env`. |
| Out of scope | `zcube` resolving a tag to a digest, or locking a tree from a reference. The user writes both values, as with slice 1 (`zbx pull` prints them). | c2-1.md (a): locking is a later command. |

## Risks

- **Goldens for `ghost`.** A service whose replica is held prints its image in several outputs.
  Make sure `source` is printed only where it is set, or every golden changes.
- **The console's width.** A 1024-byte reference must not break the replicas table. Shorten it as
  `image` is shortened.
- **Sim determinism.** If a sim hashes or prints a record, the new member must not appear when
  empty. Check whether `records.write` omits a member at its default (`applied_by` is the precedent);
  if it does not, an empty `source` changes every encoded record and every sim report.
- **Zigbox's parse versus apply's check.** A reference with a port or a nested path passes
  apply's check and may still fail `parse_reference` in a way apply cannot predict. That is by
  design, and it is reported by the supervisor. Add one `zigbox_image` table case that makes sure
  the diagnostic is kept.
