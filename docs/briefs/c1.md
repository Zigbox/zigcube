# C1 · Fleet: the milestone brief

*Written 2026-10-30 by the supervisor from HANDOFF's C1 section, `docs/authority.md` (revision 3) and the live design doc (rev 86). Each slice gets its own brief, `docs/briefs/c1-<n>.md`, cut from this one. An implementer reads its slice brief first and this file for context.*

## Goal

Workloads spread across nodes and survive the loss of one (HANDOFF, C1). `docs/authority.md` §6 lists what C1 builds and what it only records; this brief does not repeat it. Where this brief and `authority.md` disagree, stop and report.

## Settled here

| Topic | Decision | By |
| --- | --- | --- |
| Fencing constants | lease `ttl` 10 s, `fence_stop_ms` 2 s, clock-rate `skew` 1 %, `fence_margin` 3 s, `lost_grace_ms` 1 s. The inequality of `authority.md` §3 then leaves 0.9 s for kill latency (3 ≥ 2 + 0.1 + kill). All five live in `src/constants.zig`. `ttl` and `lost_grace_ms` are configurable on the server; the agent learns `ttl` from its lease grant, never from its own config. A config that breaks the inequality is refused at start with a `ZC-` diagnostic. | owner, 2026-10-30 |
| A replica that fits no node | It stays unassigned and its `/replicas` record is untouched. The scheduler writes one `hold_pending` decision per change in the reason, with the shortfall as evidence: per node, the resource that fails and by how much, or why the node is excluded (`lost`, `fenced`, an open audit finding, over-allocated). `zcube why replica` renders it. The scheduler retries on any change to `/nodes`, `/node-status`, `/allocations` or `/audit`, never in a timed loop. | supervisor |
| Request IDs | `r-<instance>-<counter>` stays, but the shell draws `instance` from `getrandom` (32 bits), not the clock. Two servers started in the same millisecond must not collide. | supervisor |
| Watch fan-out | An agent long-polls only `/assigned/<node>/` (`authority.md` §2). Benchmark, run by `zig build bench-watch` and not in `check`: 50 agents and 2,000 assignments in one process over SQLite; one new assignment wakes exactly one agent's poll; p99 time from commit to the agent's response under 250 ms on the CI runner. A miss is reported, not tuned around. | supervisor |
| Demo environment | `demo/up.sh` brings up the server (SQLite or Postgres) and three agents with separate state directories on one machine, from nothing, and `demo/down.sh` removes all of it. `demo-c1` drives the same processes from Zig, as `demo-c0` does; the script is for a person. "Power off" is `kill -9` of the agent **and** its supervisors' containers (HANDOFF's allowance of agents on one machine). | supervisor |
| The partition test | Agent alive, server unreachable: the agent's server address is a local TCP proxy that `demo-c1` controls, and a partition is the proxy dropping traffic both ways. The test asserts, from process facts on the host: the agent stops its containers before `s + ttl − fence_margin + fence_stop_ms + 0.9 s`; the replacements start no earlier than the server's expiry plus `lost_grace_ms`; the overlap of the old and new instance is zero on a healthy host. It also asserts the agent re-registers under a new tenure and its late observations are refused (I2). | supervisor |
| Lease timeout printed at failover | The `mark_lost` decision carries the `ttl` and the time the server last heard from the agent; `zcube why node` and the demo transcript print them. | supervisor |

## Local mode (owner, 2026-10-30)

The live design doc (rev 76) had put local mode in C1 with names and grants between services; `HANDOFF.md` keeps networking and real Zigbox out of C1. The owner settled it (live doc rev 86):

- **In C1:** `zcube local up` starts `zcube-server` on SQLite and one agent on the same machine with one command, no database to install and no administrator step; `zcube local down` stops both and keeps the state. It runs `FakeRuntime` until the agent links Zigbox. `demo-c1` step 5 applies `hello.zon` in local mode and sees it run.
- **Moved to C4:** names and grants between local services, and the app-and-postgres demo step.
- **The demo stays HANDOFF's:** three agents on one machine. VMs come with real Zigbox.

## Slices

Each fits one implementer session. Gates are `zig build check` from slice 2 on.

1. **`zig build check`.** Brief: `c1-1.md`.
2. **Keys and writers.** The C1 prefixes and fields (`/nodes` lease-bound, `/node-status`, `/assigned`, `/allocations`, `/audit/allocations`, `/decision-summaries`, `tenure` and `assignment` on `/observed`, `cause_evidence` on decisions), a writer-role table in the core that every transaction is checked against (I4, as an assertion), compare-set helpers. Stored values gain a version; C0's values still read. `docs/keys.md` rewritten from `authority.md`.
3. **Scheduler.** Fit on CPU and memory against declared capacity, spread (fewest assignments of the service, then least allocated, then node name), the placement, move and release transactions with the full compare set, `/allocations` maintained, `hold_pending` with the shortfall.
4. **Node controller and auditor.** Lease expiry to `lost`, then `lost_grace_ms`, then the scheduler releases and replaces; `/observed` of a lost node removed a page at a time; the auditor and its `ZC-B` finding; `zcube check allocations`, `zcube repair allocations <node> --confirm`; decision summaries and reachability-based retention.
5. **sim-c1.** Faults and invariants I1a–I7 from `authority.md` §4, its three negative tests, the evidence acceptance test, native against WASM, as `zig build sim-c1`.
6. **Agent.** Registration with a lease, keepalives, tenure-checked observed writes, self-fencing on `CLOCK_BOOTTIME` with `s` and the lease id persisted, re-registration empty after a fence.
7. **Surfaces.** `zcube get nodes`, `get replicas -o wide`, `why node`, `check`, `repair`; `completeness` in `why` (text, JSON, `docs/api.md`, the console); `bench-watch`; `demo/up.sh`, `demo/down.sh`; `zcube local up` and `local down`.
8. **demo-c1.** HANDOFF's four steps, the partition test and the local-mode step, three agents on one machine, as `zig build demo-c1 -Dbackend=sqlite|postgres`, in CI; `docs/demos/c1.md`.

## Non-goals

Everything `authority.md` §6 lists under "Recorded, not built"; rebalancing; eviction; a second server; real Zigbox; networking between workloads; names and grants in local mode (C4).
