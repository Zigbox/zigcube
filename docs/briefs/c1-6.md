# C1 slice 6 · Agent: registration with a lease, keepalives, tenure, self-fencing

*Cut from `c1.md` (slice 6, "Settled here": fencing constants, the partition test) and
`authority.md` §3 (tenure, the self-fencing window) and §4 (I1b, I2). The two agree; nothing here
overrides either.*

## Goal

An agent that is cut off from the server, or whose lease has ended, stops its containers before
the server may place replacements, and an agent that comes back cannot write over what was decided
without it.

## What to build

1. **Lease from the grant.** The agent registers `/nodes/<node>` on a lease and keeps it alive. It
   learns `ttl` from the grant reply, never from its own config (the agent's `lease_ttl_ms` option
   goes). The server grants its configured `ttl` (`constants.lease_ttl_ms` by default).
2. **Tenure.** The tenure is the revision of the registration's put (`/nodes/<node>`
   `mod_revision`). Every observed write carries it: the agent endpoint adds the compare that
   `/nodes/<node>` still has that `mod_revision` (`compare_sets.observed_write`), the records carry
   `tenure`, and a write from a superseded tenure is refused with a `ZC-` diagnostic (I2). The
   agent treats that refusal as "my tenure is gone": it fences and registers again.
3. **Self-fencing.** The agent records `s`, the time it **sent** the last keepalive (or grant) that
   succeeded, on `CLOCK_BOOTTIME`. At `s + ttl − fence_margin` with no newer success it stops every
   container, killing after `fence_stop_ms`, then registers again under a new tenure with nothing
   running. The check runs first in every step and needs no server; a call to the server never
   waits past the deadline.
4. **Persistence.** `s`, the lease id, the granted `ttl` and the tenure are in `AgentState`. A
   restarted agent continues with them; if the deadline has passed (or the clock reads earlier than
   `s`, a reboot) it fences at once.
5. **Constants and config.** The five of `c1.md` are in `src/constants.zig` (already). `ttl` and
   `lost_grace_ms` become server options; a config that breaks `fence_margin ≥ fence_stop + ttl ×
   skew + kill latency` is refused at start with a `ZC-` diagnostic.
6. **The cluster simulation.** The simulated agents lease, fence and persist through the same
   code; `sim-cluster` and `sim-teeth` keep passing. A violation the simulator finds is reported
   with its seed.

## Tests

- The fence deadline arithmetic, including a clock-rate skew within the bound and one beyond it.
- `s`, the lease id and the tenure survive an agent restart; an expired one fences at once.
- Re-registration after a fence is empty (no container left, new tenure).
- A late observation from an old tenure is refused and changes nothing.
- The server refuses a config that breaks the inequality.
- `sim-cluster` seeds exercising partitions with leases on.
