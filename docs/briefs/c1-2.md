# C1 slice 2 · Keys and writers

*Written 2026-10-30 by the supervisor. Read this first, then `docs/briefs/c1.md` for the milestone, then `docs/authority.md` §1, §2, the "Tenure" and "Admissible observations" parts of §3, and §5's "A decision carries its evidence" and "Decisions are immutable". `authority.md` is the model; where this brief and it disagree, stop and report.*

## Goal

C1's data layer, with no change in behaviour: the new keys and value shapes, the writer-role table that every transaction is checked against, the compare sets the later slices commit with, and versioned values that still read C0's records. After this slice, slices 3 to 6 (scheduler, node controller and auditor, sim-c1, agent) only write code that uses these. `demo-c0`, `sim-c0` and `agent-smoke` behave exactly as before.

## What to build

1. **Keys and records** (`src/records.zig`, and new files if it grows past what reads well; core modules stay `wasm32-freestanding`-clean). The value shapes are in `authority.md` §2, and slice 2 settles the fields:
   - `/assigned/<node>/<replica>`: `replica`, `service`, the resolved `requests`, `reason`.
   - `/allocations/<node>`: `allocated` (a `Requests`), `count`, `node_revision` (the `/nodes/<node>` revision whose capacity it was checked against).
   - `/audit/allocations/<node>`: `recorded` and `reconstructed` (each `allocated` and `count`), `revision`, `decision`.
   - `/node-status/<node>`: `state` (`ready`, `lost`, `fenced`), `tenure`, `at_ms`, `decision`.
   - `/decision-summaries/<kind>/<name>/<action>/<cause-kind>`: `count`, `first_at_ms`, `last_at_ms`, `newest` (a decision id).
   - `/observed` gains `tenure` and `assignment` (both revisions). A `Decision` gains `cause_evidence`, a JSON object of at most `decision_evidence_bytes_max` (1024) bytes. Both are optional, because C0 records do not have them.
   - Each prefix gets a constant and key builders, like the existing ones. Names follow the existing rules (`name_problem`), and every key stays within the 512-byte key limit by construction: assert it.
2. **Versioned values.** Every record already carries `"v": 1`.
   - A record whose shape changes in C1 writes `"v": 2`. That is `Observed` and `Decision`; new records start at 1.
   - A reader accepts every version up to the one it writes. A newer version is refused with one line naming the key and both versions, through a `ZC-` code registered as DIAGNOSTICS.md says, with its errors-site page. It is not `ZC-E0301`, because the value is not malformed.
   - **C0 records still read.** Prove it with fixtures captured from a real C0 store, not written by hand (REVIEW.md: fixtures come from real output). Take them from a `zig build agent-smoke` or `demo-c0 -Dbackend=sqlite` run, for example with `sqlite3` on its store. Commit them under `src/testdata/` and say in the report how they were captured.
3. **The writer-role table** (`src/writers.zig`, core):
   - **Roles:** `api`, `replica_controller`, `scheduler`, `node_controller`, `auditor`, and `agent` bound to one node name. The table maps each prefix of `authority.md` §2 to its sole writer role.
   - **Every role** may also write `/decisions/`, `/decisions-by-subject/` and `/decision-summaries/`, in the transaction of the action they record.
   - **An agent** may write only `/nodes/<its node>` and `/observed/<its node>/…`.
   - **The check:** a pure function, `writers.allowed(role, request)`, which says whether every put and delete in a `TxnRequest` is the role's. On a refusal it returns which key and which writer owns it.
   - **I4 as an assertion:** every transaction the core and shell commit passes its role, and a transaction that fails the check is an assertion failure, not an error. A wrong writer is a defect.
   - **Call sites:** today these are `controller.zig`, `agent_api.zig`, `agent.zig`, `why.zig` and `core_smoke.zig`. Find every one (`grep -rn '\.txn('`); the store's own wrappers (`server_store.zig`, `sim_world.zig`) pass through. Give the role at the call site, never "any". Test helpers that write fixtures get a role named for what they stand in for.
   - C0 has no scheduler. C0's replica controller still writes `node` into `/replicas` and stays legal: `/replicas` is its prefix. Slice 3 moves placement out.
4. **Compare sets** (`src/compare_sets.zig` or inside `writers.zig`, core). These are pure builders that take the revisions a planner read and return the `Compare`s. Each asserts its count is within `store_txn_compares_max`.
   - placement on one node: 6 compares (`authority.md` §2, "The placement compare set");
   - move: both nodes' sets, at most 10;
   - release: 2;
   - an agent's observed write: `/nodes/<node>` at the tenure revision.
5. **Constants** (`src/constants.zig`):
   - the five fencing constants of `c1.md`'s "Settled here" table, plus `decision_evidence_bytes_max`;
   - a `comptime` assertion of `fence_margin ≥ fence_stop_ms + ttl × skew + 0.9 s` in integer milliseconds and parts per thousand, with the 0.9 s budget for kill latency named.

   The server's configuration check comes with the node controller, not here.
6. **`docs/keys.md` rewritten from `authority.md`.**
   - Every prefix gets its value shape as JSON, its sole writer and its lifetime. The writer-role table appears in it once.
   - The "C1 changes this layout" section goes away, and its content lands in the sections.
   - Say, per key, which slice first writes it. Today nothing writes `/assigned` and the other new keys; slice 3 does.
   - Correct the stale status paragraph at the top: C0's keys are implemented.
   - The JSON examples in it are copied from values the tests encode, not typed.

## Tests

- **Encoding:** each new record encodes and reads back, and the size of an encoded `/assigned` value is checked. C0 fixtures read. A future `"v"` is refused with the diagnostic.
- **The writer table:**
  - for every prefix, its writer is allowed and every other role is refused;
  - an agent is refused another node's `/observed`;
  - a transaction with one stray op is refused as a whole.
- **Conformance, on all three backends** (`src/store_conformance*.zig`):
  - a placement transaction built with the helper commits when nothing moved;
  - it writes nothing when any one of its six compared keys moved: one case per compare, the audit finding by appearing;
  - **the phantom case:** two placements planned on the same `/allocations` revision, where the second must fail.
- **No behaviour change:** `sim-c0`, `agent-smoke` and the C0 why/snapshot tests pass unchanged. If a snapshot changes because `Observed` or `Decision` now writes `"v": 2`, update it, and name every changed snapshot in the report.
