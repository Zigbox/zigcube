# C2 slice 3 · `Runtime.signal`: a non-blocking stop for the fence (P2)

*Owner decision (2026-11-02, `docs/DECISIONS.md`): P2 is approved, to be done after C1 slice 6
merged (it has, PR #35). Read `AGENTS.md`, `HANDOFF.md` (Ask-first binds), `DIAGNOSTICS.md`,
`docs/STYLE.md`, `REVIEW.md`, `docs/agent.md` (gap 1 and the Zigbox runtime's "Stop" row) and
`docs/briefs/c2.md` (slice 3) first. Written 2026-11-03 from `claude/c2-2-source` at 4af7637, which

here needs a Zigbox release or a further owner decision.*

## Goal

Close `docs/agent.md` gap 1 for N containers. Today the fence calls `Runtime.stop` for each
container, and each call may wait up to `stop_wait_ms` (500 ms), so a fence over N containers that
ignore SIGTERM costs N times that bound, in the single thread that also keeps the lease. After this
slice the fence **signals every container** (a call that does not wait), then **looks at the
runtime** each step until one deadline, `fence_stop_ms`, and kills what is left. One deadline
for N containers, not N.

## What exists

- `src/runtime.zig`: `Runtime.VTable` (`start`, `stop`, `inspect`, `list`, `events`) and the
  wrappers that assert `finish` (a failed call leaves a diagnostic, a successful one none).
- `src/agent.zig` `fence_step` (`:~395`): lists the node's containers; for each running one calls
  `stop(handle, grace)` once (`fence.asked`), then again with grace 0 at `kill_at_ms`. The
  `fault_ignore_stop` teeth fault skips it.
- The three runtimes and two wrappers that fill the vtable: `fake_runtime.zig` (`stop_impl`: signal
  the supervisor's child, wait at most `stop_wait_ms`), `sim_runtime.zig` (virtual time; a
  `slow_stop` container ignores the polite stop), `sim_node.zig` (the sim runtime behind the
  agent's crash points), `zigbox_runtime.zig` (`stop_impl`: `lifecycle.signal` for TERM,
  `host.signal` for KILL, then one bounded `wait_gone`), and the spy in `agent_fence_test.zig`.
- Zigbox (pinned): `lifecycle.signal(ref, number)` forwards only HUP, INT, QUIT and TERM
  (`signals.forwarded`; it asserts the rest away), and sends SIGKILL in its place for a PID 1 that
  has no handler. It does not wait. `host.signal(pid, number)` sends any signal. Both are what
  `ZigboxRuntime.stop` already uses, so nothing new is needed from Zigbox.

## Settled here

| Topic | Decision | Why |
|---|---|---|
| Shape | `signal: fn (context, handle: Handle, number: u8, diag: *Diag) Error!void`, and the wrapper `Runtime.signal(handle, number, diag)`. | P2 as approved. |
| Which numbers | Only `runtime.signal_term` (15) and `signal_kill` (9). Another number is a caller bug: the wrapper asserts it, as it asserts a bad spec. | Zigbox forwards a fixed set and the agent needs two. A wider contract is a later proposal. |
| Semantics | Delivers the signal to the container's main process and returns at once. It does not wait, and success says nothing about whether the container has stopped: the caller reads `inspect` or `list`. Signalling a stopped container does nothing; an unknown one is `NotFound`. | A non-blocking call is the point. |
| Not-yet-running containers | A container that is `starting` (no process yet) receives TERM or KILL as the existing `stop` treats it: the supervisor is killed (real runtimes), the record stays. | Same rule as `stop`, which the fence relied on. |
| `stop` | Unchanged, in the vtable, and still used by the reconcile loop's `stop_once` (a stop with a grace that the caller checks later). | P2 asks for `signal`; the pending-stop logic is not part of this slice. |
| Fence | Step 1: signal TERM to every running container of this node, none waiting, and set `asked`. Later steps: `list`; at `kill_at_ms` signal KILL to each one still running. The kill time and `fencing.zig` are unchanged; the inequality `fence_margin_ms >= fence_stop_ms + skew + kill_latency` holds as before. | One deadline. |
| Failure | As today: the first failed signal is the step's error, later ones are dropped, and one container that cannot be signalled does not keep the others running. `NotFound` means it has gone. | Unchanged behaviour. |
| Teeth | The existing agent fault `fault_ignore_stop` also covers the fence's signals (it already skips the fence loop); `sim-teeth` keeps failing a seed. A new test-only fault in `SimRuntime` that makes `signal` do nothing is not added: the agent-side fault covers the agent's call, and the runtime-side "signal does nothing" is a test (below) that must fail on a runtime that drops it. | Fewer switches, same coverage. |
| Gaps | None expected in the Zigbox adapter. Anything found is reported, not worked around. | AGENTS.md. |

## Steps

One commit per step, `zig build tidy` before each.

1. **The contract and the simulated runtime.** `signal_term`, `signal_kill`, the vtable entry, the
   wrapper and its asserts, the doc comment. `SimRuntime` and `SimNode` implement it (TERM ends a
   container that does not ignore it, as `stop` with a grace does; KILL ends any; `slow_stop`
   containers ignore TERM). The `Refusing` runtime and the `SourceSpy` in `agent_fence_test.zig`
   gain the entry. *Mechanical:* the vtable entry in the wrappers.
2. **FakeRuntime.** TERM or KILL to the container's process group's child as `stop_impl` does
   today, without the wait. Tests in `fake_runtime_test.zig`: TERM to a well-behaved container,
   KILL to one that ignores TERM, a stopped one (nothing), an unknown one (`NotFound`), and a
   timing check that a signal returns in under `stop_wait_ms`.
3. **ZigboxRuntime.** `signal_impl` over the same `resolve` and `adopt` as `stop_impl`, with no
   wait. Tests over `HostSim`: TERM, KILL, a `starting` container, a stopped one, unknown, and no
   `wait_gone` (the clock does not move).
4. **The fence.** `fence_step` signals. Tests (`agent_fence_test.zig`, sim): a fence over 16
   containers ends within one deadline of its start; a container that ignores TERM is killed at
   the deadline; the existing fence tests are unchanged. `sim-cluster` already fences nodes;
   confirm the report for a fixed seed is the same or explain the difference.
5. **Docs.** `docs/agent.md`: gap 1 says what was done, the Zigbox "Stop" row, the fence table.
   `docs/core.md` where it names the simulated stop.

## Tests that must exist at the end

- A fence over 16 containers ends within one `fence_stop_ms` of its start, on `FakeRuntime`
  (real processes) and in sim.
- A container that ignores SIGTERM is killed at the deadline, not before.
- The signal tests per runtime listed above, including "signal does not wait".
- `sim-teeth` still fails a seed (the agent fault).
- Unchanged: the `demo-c0` transcript, `sim-c0` reports for a fixed seed, and the pending-stop
  logic of `stop_once`.

## Non-goals

- No change to `stop`'s contract or to the reconcile loop's stops.
- No new signal numbers, no signal forwarding policy, no `signal` on the API or CLI.
- No change to `fencing.zig`'s constants or the fence's kill time.
- The core stays `wasm32-freestanding`-clean: the new entry is a vtable pointer, no file, thread
  or real clock.
